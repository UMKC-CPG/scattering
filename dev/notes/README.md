# Working Notes

Dated, non-binding write-ups: design discussions, state-of-the-
project snapshots, tool surveys, recipes, and anything else that
captures thinking in progress.

Nothing here specifies behavior. When something in a note becomes a
decision, promote it into the chain (`VISION`, `ARCHITECTURE`, a
`design/` section, a `pseudocode/` section) and leave the note in
place as provenance for how the decision was reached.

Name files `topic.md`, or `topic-YYYY-MM-DD.md` when the date is part
of what the file means — a snapshot of project state, for instance.
Put the date in the header of every note regardless, because a note
without one cannot be judged stale.
